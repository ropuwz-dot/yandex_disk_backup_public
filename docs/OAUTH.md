# Собственное OAuth-приложение Яндекса

В публичной редакции нет встроенного ClientID или готовых учётных данных. ClientID — публичный идентификатор приложения, но каждый пользователь задаёт свой.

1. Откройте официальный сервис: https://oauth.yandex.ru/ . Создайте приложение по документации https://yandex.ru/dev/id/doc/ru/register-client .
2. Настройте приложение для получения OAuth-токена в браузере (implicit flow). Для отображения результата используйте официальный verification redirect `https://oauth.yandex.ru/verification_code`, если интерфейс регистрации требует redirect URI.
3. Запросите только чтение Диска и информацию о Диске: `cloud_api:disk.read`, `cloud_api:disk.info`. Не добавляйте права на запись/удаление.
4. Скопируйте ClientID — 32 строчных hex-символа — в локальную программу (пункт 1). ClientSecret программе не нужен.
5. Программа откроет `https://oauth.yandex.ru/authorize?response_type=token&client_id=...`. Проверьте домен и выбранный аккаунт. Полученный токен вставляйте только в скрытый локальный ввод, без URL и посторонних символов.
6. Программа проверит аккаунт и чтение списка, затем попросит ввести показанный логин. До успешной проверки новое подключение не становится активным.

При истечении/отзыве доступа подключите аккаунт заново. Автоматическое обновление implicit-токена не обещается; `refresh_token=none` в локальной служебной структуре — совместимость с backend rclone, **не настоящий refresh credential**.

Официальная документация Диска: https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart . Интерфейс регистрации и доступность способов авторизации могут измениться. Нативный OAuth-flow этой публичной редакции в рамках подготовки не проверялся.
