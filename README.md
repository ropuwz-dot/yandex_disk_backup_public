# Как скачать файлы с Яндекс Диска на компьютер

**YandexDiskBackup-Public — Яндекс.Диск.Бокап.Паблик** — бесплатная консольная программа для Windows 10/11 x64. Позволяет скачать файлы с Яндекс Диска на компьютер или внешний диск, сохранить выбранную папку либо весь свой Диск, продолжить прерванное скачивание и проверить результат.

Публичная редакция на основе версии 1.1.7. Не является официальным продуктом Яндекса. Авторизация, права и файлы предоставляются самим пользователем; готовых аккаунтов и токенов в проекте нет.

**[Скачать программу для Windows — ZIP с исходниками и комплектом запуска](https://github.com/ropuwz-dot/yandex_disk_backup_public/archive/refs/heads/main.zip)** · [Настройка доступа к Диску](docs/OAUTH.md) · [Безопасность](SECURITY.md)

## Не получается скачать с Яндекс Диска: что делать?

Если загрузка через браузер обрывается, большая папка не скачивается одним архивом или нужно сохранить много файлов по отдельности, можно попробовать копирование через API Яндекс Диска. Эта программа использует rclone: получает список доступных файлов вашего аккаунта, скачивает их последовательно и проверяет локальную копию.

Это **альтернативный способ скачивания, а не обход ограничений доступа**. Если сам файл недоступен через API, аккаунт не имеет нужных прав или сервис возвращает ошибку, программа не может гарантировать его загрузку. Ошибки не скрываются и не считаются успешным резервным копированием.

Программа работает с **вашим авторизованным Диском**, а не с произвольной публичной ссылкой. Для подключения нужно создать своё OAuth-приложение по [инструкции](docs/OAUTH.md); готового входа без настройки здесь нет.

## Возможности

- Скачать весь Диск или выбранную папку, по одному файлу.
- Продолжить копирование без повторной передачи уже совпавших файлов.
- Не перезаписывать отличающиеся локальные файлы и не менять оригиналы в облаке.
- Показывать этап, скорость, объём, прошедшее время и активный файл; не выдавать ожидание за передачу.
- После полного прохода проверить копию и перечислить ошибки. При неполном результате спросить о повторе только неподтверждённых файлов: ДА/НЕТ.
- Изолировать копии по стабильному ID аккаунта и выбранному источнику.

## Как скачать с Яндекс Диска на Windows: быстрый старт

1. [Скачайте ZIP](https://github.com/ropuwz-dot/yandex_disk_backup_public/archive/refs/heads/main.zip) либо нажмите **Code → Download ZIP**. Распакуйте **весь архив**, сохранив структуру папок, в отдельную локальную папку.
2. В `package` запустите `SELF-TEST.cmd`. Эта проверка не подключает аккаунт и не скачивает пользовательские данные.
3. Запустите `package/START.cmd`, выберите **1** и введите ClientID **своего** OAuth-приложения Яндекса. Как его создать — [docs/OAUTH.md](docs/OAUTH.md).
4. Подтвердите открытие браузера, войдите в нужный аккаунт и вставьте полученный токен **только в скрытое поле локальной консоли**. Подтвердите показанный логин. ClientSecret не нужен.
5. Пункт **2**: выберите источник и локальную папку назначения. `/` означает весь Диск. Пункт **3**: подтвердите скачивание.

Для обычного запуска Python, администратор и отдельная установка rclone не требуются. Штатный Windows PowerShell 5.1 используется через `.cmd`. Проверенный Windows-архив rclone 1.75.2 включён в `package/vendor`, его SHA-256 и SHA-256 `rclone.exe` проверяются перед запуском.

Публичная редакция хранит новые настройки в `%LOCALAPPDATA%\YandexDiskBackup-Public` и **не импортирует** подключения других редакций. Не копируйте в проект старые настройки, `rclone.conf`, отчёты или скачанные данные.

## Частые вопросы о скачивании с Яндекс Диска

### Как скачать весь Яндекс Диск на компьютер или внешний жёсткий диск?

После подключения аккаунта выберите пункт **2**, укажите `/` как источник и локальную папку на нужном диске как место сохранения. Затем запустите пункт **3**. Для большого объёма проверьте свободное место и используйте файловую систему, поддерживающую размеры ваших файлов: например, FAT32 не подходит для файлов размером 4 ГиБ и больше. Программа не форматирует носитель.

### Как скачать папку с Яндекс Диска без создания одного большого ZIP-архива?

В пункте **2** вместо `/` укажите путь нужной папки внутри своего Диска, точно сохраняя регистр и название. Файлы передаются по отдельности, с сохранением вложенных каталогов, включая пустые. Программа не запрашивает создание общего облачного архива папки.

### Можно ли продолжить скачивание после обрыва интернета?

Да: сохраните прежние источник и папку назначения, снова откройте программу и запустите пункт **3**. Уже совпадающие файлы повторно не скачиваются; отличающиеся локальные файлы не перезаписываются автоматически. После неполного прохода можно подтвердить повтор неподтверждённых файлов ответом **ДА**.

### Почему отдельный файл всё равно не скачивается?

Причиной могут быть недоступность файла, ответ облачного API, сетевой тайм-аут, конфликт локального файла или несовместимое с Windows имя. Итоговые отчёты находятся рядом с каталогом `Files`, в `Reports`. Не публикуйте их без очистки: внутри могут быть личные имена файлов, пути и сведения об аккаунте. Недоступный файл остаётся ошибкой; программа не умеет восстанавливать удалённые оригиналы и не обходит права доступа.

### Удалит ли скачивание файлы из облака?

Нет: программа использует операции копирования и проверки, а не синхронизацию с удалением. Исходные файлы на Яндекс Диске не перемещаются и не удаляются. Подробности защиты токена и ограничения проверки описаны ниже и в [SECURITY.md](SECURITY.md).

## Что считать успехом

Итог `Verified=true` в отчёте означает успешные copy/check и согласованность учтённых данных. Наличие файлов, 100% индикатора отдельного прохода или вопрос ДА/НЕТ сами по себе не подтверждают полноту копии.

Отчёты создаются в выбранном назначении рядом с `Files`. Они содержат имена/пути файлов и сведения об аккаунте: не загружайте их в публичный репозиторий или issue без ручной очистки.

## Ограничения

- Это копия текущих доступных файлов, а не атомарный снимок. Корзина, история версий, права доступа и непредставимые обычными файлами объекты не гарантируются.
- Изменения источника во время копирования, недоступные объекты и конфликты делают результат неполным. Программа не восстанавливает недоступные оригиналы.
- Для copy тайм-аут простоя/соединения — 15 секунд. Это **не** ограничение полной длительности передачи файла. Inventory/check используют свои параметры.
- Длинные пути, запрещённые Windows имена и особенности облачного API могут потребовать отдельной диагностики.
- Запускайте одну операцию на одну папку назначения; не направляйте две независимые копии программы в одно назначение.

## Безопасность

См. [SECURITY.md](SECURITY.md). Токен хранится в локальном конфиге в открытом виде под Windows DACL, **не в зашифрованном хранилище**. Приложение проверяет защиту каталога и отказывает при ошибке; права администратора не требуются. Доступ от имени того же Windows-пользователя, администратора и SYSTEM этой защитой не исключается.

Права OAuth определяет ваше приложение. Рекомендуются только `cloud_api:disk.read` и `cloud_api:disk.info`. Копирование использует `rclone copy` и `check`, а не `sync`, `move` или удаление.

## Структура

- `package/` — запускаемый Windows-комплект, общая инструкция и контрольные суммы.
- `tests/` — локальные синтетические проверки, без пользовательских облачных данных.
- `docs/` — OAuth и фактические результаты проверки.
- `LICENSE` — MIT, сохранена из существующего публичного проекта; лицензия rclone — отдельно в `package/RCLONE-LICENSE.txt`.

## Проверка разработчиком

Для тестов нужны Python 3.9+, PowerShell 7, rclone 1.75.2 и модуль PowerShell `PSScriptAnalyzer` (правило совместимости с 5.1). Поместите инструменты в PATH или задайте `YDB_PWSH` / `YDB_RCLONE`. Затем:

```console
python tests/run.py
```

Suite использует временные локальные данные и HTTP-fixtures на loopback. Отдельный `RealYandexBackend.Tests.ps1` **не входит** в обычный suite: это необязательная внешняя отрицательная проверка официального API заведомо недействительным синтетическим токеном, а не проверка доступа к аккаунту.

Отдельно на целевой Windows можно выполнить:

```powershell
.\tests\PrivateDirectoryAcl.Tests.ps1 -NativeOnly
```

См. [docs/TESTING.md](docs/TESTING.md) для реально выполненных проверок и ограничений. Ни OAuth, ни настоящая выгрузка в рамках подготовки публичного проекта автоматически не запускаются.

## Подготовка к публикации

`.gitignore` исключает типовые настройки/токены, отчёты и скачанные файлы. Это не замена проверке: перед push просмотрите `git status`, `git diff --cached` и выполните Gitleaks для дерева и истории. Не добавляйте runtime-файлы через `git add -f`. Не переносите `.git` из частного проекта.

Рабочая программа владельца и её настройки не входят в эту поставку. Публичный репозиторий содержит только самостоятельный комплект, документацию и синтетические тесты.
